# FraudShield AI — Transaction Risk Console

A React + Tailwind frontend for the `fraudshield_api.py` FastAPI backend
(the Baseline Random Forest fraud model from `fraudshield_ai.ipynb`).

Five pages, no filler:

| Page | Route | What it shows |
|---|---|---|
| **Overview** | `/` | Fraud-monitoring summary — final test scorecard (accuracy, precision, recall, F1, ROC-AUC, PR-AUC), fraud-amount capture rate, confusion matrix, current model + threshold, live API status |
| **Transaction Analyzer** | `/analyze` | The main interactive feature — enter a transaction or load a known case, call `/predict`, see fraud probability, FRAUD/LEGITIMATE decision, LOW/MEDIUM/HIGH risk, and a transaction summary |
| **Fraud Investigation** | `/investigation` | Every transaction you've analyzed this session in a sortable, filterable table (amount, type, probability, decision, risk) — click a row to inspect its full balances and signal breakdown |
| **Model Insights** | `/insights` | Why the model decides what it decides — SHAP feature importance with directional interpretation, ROC/PR curves, metrics, confusion matrix, and the reasoning behind the 0.21 threshold |
| **System & Model** | `/system` | Production info — Random Forest (400 estimators), feature pipeline, train/val/test split sizes, live API health, deployment commands |

No login, registration, settings, notifications, or fabricated "transactions
today" — the only transaction data ever shown is either pulled from
`Fraud_Analysis_Dataset.csv` / the notebook's own test cells, or generated by
a real call you made to `/predict`.

## 1. Run the backend first

This frontend calls your existing API, unmodified:

```bash
uvicorn fraudshield_api:app --reload
```

It expects `fraudshield_production/fraudshield_rf_pipeline.joblib` and
`fraudshield_production/decision_threshold.joblib` to be present, exactly
as `fraudshield_api.py` already requires.

### Required: enable CORS

`fraudshield_api.py` as given has no CORS policy, so a browser-based
frontend (this one, running on `http://localhost:5173`) will be blocked
by the browser even though the API itself works fine from `curl` or the
`/docs` page. Nothing in your uploaded files needed to change for the
model or data — just add FastAPI's built-in CORS middleware to
`fraudshield_api.py`:

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```

Add this right after `app = FastAPI(...)`. That's the only backend change
needed.

## 2. Run the frontend

```bash
npm install
npm run dev
```

Open the printed local URL (defaults to `http://localhost:5173`). The
header shows a live green/red dot polling `/health` every 15s, so you'll
know immediately if the API or CORS isn't reachable.

If your backend runs on a different host or port, click the gear icon in
the header and set the API base URL — it's saved in `localStorage`, no
rebuild required.

## 3. Build for production

```bash
npm run build
npm run preview   # sanity-check the production build locally
```

Output lands in `dist/`. Routing uses a hash router
(`/#/analyze`, `/#/investigation`, …) so the static build works from any
host or file server with zero rewrite-rule configuration.

## Where the data comes from

- **Sample transactions** (`lib/sampleTransactions.js`) — pulled directly
  from `Fraud_Analysis_Dataset.csv` and the notebook's production-test
  cells, including the documented false-negative case.
- **Scorecard numbers** (`lib/modelMetadata.js`) — read verbatim from
  `fraudshield_model_metadata.joblib` (accuracy, precision, recall, F1,
  ROC-AUC, PR-AUC, confusion matrix, fraud-amount capture rate) and from
  the notebook's printed cell outputs (dataset size, 70/15/15 split
  counts, hyperparameters, encoded feature list).
- **SHAP feature importance and RF `feature_importances_`**
  (`lib/modelInsights.js`) — copied from the notebook's Level 12 SHAP
  section (cells 385/386) and Level 5 (cell 238). The directional reads
  for the top 6 features come from the notebook's own summary table
  (cell 400).
- **ROC / Precision-Recall curves** (`lib/modelInsights.js`) — *not*
  copied from the notebook, since those were only rendered as matplotlib
  images there, not printed as arrays. Instead they were reproduced by
  reloading `fraudshield_final_rf_pipeline.joblib`, rebuilding the
  identical stratified 70/15/15 split (`random_state=42`) from the CSV,
  and running `roc_curve` / `precision_recall_curve` against the same
  1,672-row held-out test set — verified to reproduce the same
  accuracy/precision/recall/confusion matrix as the metadata file before
  being accepted.
- **Threshold rationale** (`lib/modelInsights.js`) — summarized from the
  notebook's Level 8 "Threshold Optimization" section (cells 286–306):
  0.21 is the F1-maximizing operating point on the validation set.
- **Fraud-rate-by-type chart** — computed straight from
  `Fraud_Analysis_Dataset.csv` (`groupby('type')['isFraud'].mean()`).
- **Fraud Investigation table** — built entirely from your own session:
  every successful `/predict` call from the Transaction Analyzer is
  appended here and persisted to `localStorage`. Nothing is pre-seeded.

None of the uploaded data, model, or notebook files were modified to
build this.
